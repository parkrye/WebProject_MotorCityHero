# 모터시티 히어로

고전 오락실 스타일 횡스크롤 배틀 액션. 바닐라 HTML5 Canvas + JavaScript, 빌드 도구 없음.

## 실행

**`run-game.bat` 을 더블클릭**하면 로컬 서버가 뜨고 브라우저가 열립니다.
같은 공유기에 물린 폰·노트북에서도 콘솔에 찍힌 `http://<이 PC 의 IP>:47823` 로 접속할 수 있습니다.

```
====================================================
  모터시티 히어로
====================================================
  이 PC      http://localhost:47823
  다른 기기  http://192.168.0.12:47823
----------------------------------------------------
  종료: Ctrl+C
====================================================
```

- 포트는 **47823** 입니다. IANA 미할당이고 Windows 임시 포트 범위(49152~) 밖이라 충돌이 잘 나지
  않습니다. 이미 점유 중이면 47824, 47825… 로 알아서 옮겨가고 옮긴 포트를 알려줍니다.
- 첫 실행 때 방화벽 인바운드 허용 규칙(`MotorCityHero LAN`, TCP 47823, **개인 네트워크 한정**)이
  없으면 관리자 권한 창이 한 번 뜹니다. [예] 를 눌러야 다른 기기에서 접속됩니다.
  거부해도 서버는 그대로 뜨고, 이 PC 에서는 정상적으로 플레이할 수 있습니다.
- 캐시를 끄고 서빙하므로 에셋을 교체한 뒤에는 새로고침만 하면 반영됩니다.

옵션은 `run-game.bat` 뒤에 그대로 붙이면 됩니다.

| 옵션 | 동작 |
|---|---|
| `--port 50000` | 포트 지정 |
| `--local-only` | `127.0.0.1` 에만 바인딩. 외부에 열지 않음 (방화벽도 건드리지 않음) |
| `--no-browser` | 브라우저 자동 실행 안 함 |
| `--no-firewall` | 방화벽 규칙을 확인·등록하지 않음 |
| `--close-firewall` | 등록해둔 방화벽 규칙을 제거하고 종료 |

`index.html` 을 `file://` 로 바로 열어도 동작합니다. 다만 이 경우 다른 기기에서는 접속할 수 없습니다.

서버 본체는 `tools/serve.py` 이고 표준 라이브러리만 씁니다. Python 3 만 있으면 됩니다.

```bash
python tools/serve.py --local-only   # macOS · Linux 에서도 동일하게 동작 (방화벽 처리는 Windows 전용)
```

## 조작

**1인용입니다.** 이 표에 없는 키와 마우스는 전부 무시합니다. 판정은 전부 `event.code` 기준이라
NumLock 상태와 무관하고, 문자열 위쪽의 숫자열(`Digit0`~`Digit9`)은 어디에도 매핑되어 있지 않습니다.

| 동작 | 키보드 | 터치 |
|---|---|---|
| 이동 | `W` `A` `S` `D` | 왼쪽 스틱 |
| 펀치 · 확인 | `J` | `A` |
| 킥 | `K` | `B` |
| 코인 투입 | `P` | 구석의 작은 `P` |

- **펀치와 킥은 대미지와 사거리가 같고 닿는 깊이만 다릅니다.** 펀치는 안쪽(위)으로,
  킥은 앞쪽(아래)으로 판정 창이 `CONFIG.player.attack.depthBias` 만큼 옮겨갑니다.
  줄지어 선 적을 정리할 때 둘을 번갈아 쓰면 사각이 줄어듭니다.
- **선입력을 받습니다.** 낼 수 없는 타이밍(공격 모션 중·후딜 중)에 누른 펀치/킥은
  `CONFIG.input.bufferMs`(220ms) 동안 기억했다가 가능해지는 순간 바로 나갑니다.
  공격 판정이 끝난 프레임부터는 모션이 끝나기를 기다리지 않고 다음 공격으로 이어지므로,
  빠르게 두 번 누르면 사이 딜레이가 눈에 띄게 줄어듭니다.
- 메뉴·랭킹·이름 등록 화면도 같은 키(또는 스틱 + `A`)로 조작합니다.
- 로비 메뉴 맨 아랫줄은 **소리 · 화면 토글 버튼** 줄입니다. 그 줄에서만 좌우가 버튼 선택으로 쓰입니다.

모든 스프라이트는 오른쪽이 정방향이며, 왼쪽을 볼 때만 `ctx.scale(-1, 1)` 로 좌우 반전해서 그립니다.
위/아래만 입력했을 때는 보던 방향을 유지합니다.

### 모바일

터치 기기(`pointer: coarse`)로 들어오면 화면 위에 조이패드가 뜹니다. `?touch=1` / `?touch=0` 으로
강제할 수 있습니다. 버튼은 DOM 이고, 키보드와 **똑같은 입력을 `Input` 에 넣습니다.** 게임 쪽은
어디서 들어온 입력인지 모르므로 로비·이름 등록·랭킹도 따로 손대지 않고 그대로 조작됩니다.

- 왼쪽 스틱은 가운데를 원점으로 보고 밀린 방향을 켭니다. 한 손가락으로 대각선까지 됩니다.
- **세로 화면**에서는 4:3 레터박스로 남는 아래 공간에, **가로 화면**에서는 좌우로 남는 공간에
  버튼을 놓습니다. 어느 쪽이든 게임 화면을 가리지 않습니다.
- 코인 `P` 는 실수로 누르면 곤란하니 구석에 작게 뒀습니다.

## 게임 플로우

```
LOBBY      타이틀 + GAME START / RANKING / EXIT + 소리·화면 토글
  │
  ├─ GAME START ─> 스테이지 1
  │    INTRO       스테이지 배경 + 스테이지 이름 → 플레이어가 화면 밖에서 걸어 들어옴
  │    COUNTDOWN   3 → 2 → 1 → START
  │    PLAYING     5분 카운트다운. 60초 경과(4분 남는 순간) 최종보스 등장
  │      ├ 보스 격파 ─> STAGE CLEAR ─> 다음 스테이지 (INTRO 로)
  │                    스테이지 배경 위에 결과만. 일러스트는 마지막 스테이지에서만
  │      ├ 생명 0    ─> CONTINUE
  │      └ 시간 0    ─> CONTINUE
  │    CONTINUE    코인이 있으면 즉시, 없으면 11초 카운트다운 동안 코인을 기다린다
  │    FADEOUT     컨티뉴 실패 · 마지막 스테이지 클리어. 암전
  │    GAMEOVER    점수 표시. 액션키 또는 5초 뒤 이름 등록으로
  │                마지막 스테이지를 끝내고 왔으면 GAME CLEAR 로 뜬다
  │    NAME ENTRY  오락실식 문자표로 최대 16글자
  │    RANKING     방금 올린 기록을 강조해서 보여줌 → BACK 으로 로비
  │
  ├─ RANKING     로비에서 바로 보기
  └─ EXIT        인사 화면. 액션키로 로비 복귀
```

어떻게 끝나든 **끝나면 항상 이름 등록 화면**이 나오고, 이름을 넣으면 랭킹으로 갑니다.
다만 마지막 화면 문구는 갈립니다. 컨티뉴에 실패해서 온 거면 `GAME OVER`,
**스테이지 6까지 다 깨고 온 거면 `GAME CLEAR`** 이고 클리어 곡이 그대로 이어서 흐릅니다.

- 스테이지는 배경을 가로 3타일 반복해 만든 폭 3072 월드이며, 카메라가 플레이어를 **화면 가운데**에
  두고 따라갑니다 (`CONFIG.camera.anchorRatio`). 맵 좌우 끝에서는 화면 밖이 보이지 않도록 멈춥니다.
- 상하 이동은 도로 영역으로 제한되고, 안쪽(위)일수록 캐릭터가 작게 그려집니다 (벨트스크롤 원근).
- 발끝 y 기준으로 정렬해 앞뒤 겹침을 처리합니다.

### 스테이지

| 스테이지 | 무대 | 다수 | 소수 | 최종보스 |
|---|---|---|---|---|
| 1 | TEXAS | enemy_1 | enemy_2 | enemy_3 |
| 2 | DETROIT | enemy_2 | enemy_3 | enemy_4 |
| 3 | NEW YORK CITY | enemy_3 | enemy_4 | enemy_5 |
| 4 | TESLA SPACESHIP | enemy_4 | enemy_5 | enemy_6 |
| 5 | MOON BASE | enemy_5 | enemy_6 | enemy_7 |
| 6 | MYSTERY ZONE | 전부 섞임 | | 없음 |

- **제한 시간 5분**이 0 으로 줄어듭니다. **60초가 지나는 순간(4분 남았을 때) 최종보스**가 오른쪽에서 걸어 나오고,
  쓰러뜨리면 스테이지 클리어입니다. 0 이 되면 실패입니다.
- 최종보스는 같은 에너미를 **체력 7배 · 크기 1.55배**로 세운 것입니다. 머리 위 작은 체력바 대신
  화면 위에 큰 게이지가 하나 뜹니다.
- **스테이지 6(수수께끼 공간)** 은 보스가 없고 모든 에너미가 나옵니다. **1분이 지나거나 쓰러지면
  코인을 쓰지 않고 그대로 클리어**되고, 거기서 게임이 끝납니다. 점수 파밍용이라 항상 마지막입니다.
- 스폰 머릿수에 보스는 넣지 않습니다. 넣으면 보스 하나로 자리가 차서 잡몹이 끊깁니다.
- 잡몹은 **화면 밖 좌우 양쪽**에서 걸어 들어옵니다. 등장 지점은 카메라 기준이라
  **맵 경계 너머(`x < 0`, `x > 3072`)여도 그대로 세웁니다.** 여기서 월드 안으로 가두면
  맵 끝에 붙어 있을 때 한쪽 등장이 통째로 막혀 늘 같은 방향에서만 오게 됩니다.
  걸어 들어오는 동안만 경계를 풀고, 월드 안으로 한 번 들어온 뒤부터는 평소대로 가둡니다.
  최종보스만 언제나 정면(오른쪽)에서 나옵니다.

### 에너미

체력만 불리면 일곱 종류가 다 똑같이 걸어와서 구분이 안 됩니다. 그래서 성격을 **두 겹**으로
나눕니다. 둘은 겹쳐서 돕니다.

| 겹 | 무엇을 정하는가 | 어디에 |
|---|---|---|
| `behavior` | **어디로** 다가오는가 (경로) | `CONFIG.enemyBehavior` |
| `motion` | **어떻게** 움직이고 **어떤 자세로** 때리는가 | `CONFIG.enemyMotion` |

#### 다가오는 규칙 (`behavior`)

| 번호 | 규칙 | 성격 |
|---|---|---|
| 1 | `dash` | 멈췄다 짧게 치고 들어온다 |
| 2 | `straight` | 곧장. 기준점 |
| 3 | `zigzag` | 깊이축으로 물결치며 붙는다. 정면으로만 서 있으면 잘 안 맞는다 |
| 4 | `straight` | 느리고 잘 밀리지 않는 덩치 |
| 5 | `hitAndRun` | 한 번 때리면 물러났다 다시 붙는다 |
| 6 | `flank` | 앞을 막지 않고 등 뒤로 돌아 들어간다 |
| 7 | `stalk` | 사거리 밖을 맴돌다 이따금 파고든다 |

같은 종류가 여럿 나와도 한 몸처럼 움직이지 않도록 위상을 흩어둡니다.

#### 겉모습 (`motion`)

원본 스프라이트가 종류마다 "걷기" 한 벌뿐이라, **이동 리듬과 공격 자세를 코드로 만들어** 붙입니다.
발끝을 원점으로 뜸(`hover`) · 기울기(`tilt`) · 앞뒤(`lean`) · 좌우 스텝(`sway`) · 찌부러짐(`squash`)을
매 프레임 계산해 그립니다.

| 번호 | 누구 | 이동 | 공격 |
|---|---|---|---|
| 1 | 고양이 | 짧고 빠르게 폴짝 | `pounce` 웅크렸다 앞으로 덮친다 + 발톱 |
| 2 · 3 | 꼬마아이 | 크고 느리게 폴짝. 착지할 때 푹 눌린다 | `headbutt` 뛰어올라 머리로 박는다 |
| 4 | 원숭이 | 좌우로 흔들리는 육중한 걸음 | `thrust` 팔을 뒤로 뺐다 길게 내지른다 + 잔상 |
| 5 | 여성 | 가장 높고 길게 체공하는 폴짝 | `divekick` 떠올랐다 내려찍는다 |
| 6 | 둔기 여성 | 무기를 어깨에 걸친 채 뚜벅뚜벅 | `swing` 뒤로 감았다 크게 휘두른다 + 궤적 |
| 7 | 강남스타일 | 두 박자 갤럽 + 좌우 스텝 | `spin` 제자리에서 돈다 + 충격파 |

**그림만 흔드는 게 아니라 판정도 같이 갑니다.**

- **폴짝이는 부류(1 · 2 · 3 · 5)는 공중에 떠 있는 동안에만 전진합니다.** 멈춰 있는 만큼
  공중에서 더 빨리 가므로 평균 속도는 `stats.speed` 그대로입니다. 대신 다가오는 게 뚝뚝
  끊겨서, 착지 순간을 노리면 반격하기 쉽습니다.
- 자세마다 사거리(`reachMul`)와 깊이(`depthMul`)가 다릅니다. **원숭이의 내지르기는 가장
  길고 얕고**(사거리 1.3배 · 깊이 0.68배), **둔기의 휘두르기는 가장 깊습니다**(깊이 1.9배).
  가로로 쓸어버리는 대신 준비 동작이 길어 보고 피할 수 있습니다.
- **강남스타일의 회전(`omni`)만 앞뒤를 가리지 않습니다.** 등 뒤로 돌아도 맞습니다.
- 덮치기(`pounce`) · 내지르기(`thrust`) · 내려찍기(`divekick`)는 판정이 켜져 있는 동안
  **실제로 앞으로 나갑니다**(`lunge`).
- 타격 구간에만 궤적이 뜹니다. 사거리와 깊이를 실제 판정에서 그대로 가져오므로
  **보이는 만큼만 맞습니다.**

### 생명 · 코인 · 아이템

- 생명 3개로 시작합니다. **무엇에 맞든 한 대 = 생명 1** 이고,
  hit 애니메이션이 도는 동안(560ms)은 무적입니다.
- 생명이 0이 되면 **hit 애니메이션의 마지막 프레임(완전히 쓰러진 자세) 그대로 멈춥니다.**
  컨티뉴로 일어나기 전까지, 게임 오버 화면까지도 그 자세를 유지합니다.
  - 코인이 있으면 1개를 쓰고 **점수와 스테이지를 유지한 채** 생명 3개로 그 자리에서 이어갑니다.
  - 코인이 없으면 11초 카운트다운. 그 사이 `P` 로 코인이 들어오면 똑같이 이어서 시작합니다.
    카운트다운 음성이 앞을 1초 띄우고 세기 시작하므로, 화면도 첫 1초는 숫자를 내지 않고
    남은 10초를 **10 부터 0 까지** 고르게 나눠 보여줍니다 (`CONFIG.continue.leadInSeconds`).
  - 이어갈 생각이 없으면 11초를 다 볼 이유가 없습니다. **코인(`P`) 말고 아무 키나
    (`W` `A` `S` `D` `J` `K`, 터치는 `A` · `B`) 누를 때마다 카운트다운이 1초씩 당겨집니다**
    (`CONFIG.continue.skipSeconds`). 세는 음성도 같은 만큼 앞으로 감아서 화면과 어긋나지 않습니다.
  - 카운트다운이 끝나면 암전 후 GAME OVER.
- **시간이 다 되어 실패한 경우에만 컨티뉴가 스테이지 시계를 되돌립니다.** 안 그러면 이어가자마자
  또 끝납니다. 정리된 보스는 조건이 맞으면 다시 나옵니다.
- 적을 쓰러뜨리면 `CONFIG.pickup.drops` 표를 위에서부터 한 번의 주사위로 훑어 아이템이 떨어집니다.
  **공격력 3.5% · 회복 5% · 보호막 2.2% · 이동속도 2.2%** (합계 12.9%). 먹지 않으면 깜빡이다 사라집니다.
- 아이템 범위는 **두 겹**입니다. 바깥의 넓은 범위(`CONFIG.pickup.magnet`)에 들어오면
  **플레이어 쪽으로 끌려오기 시작하고**, 끌려오다 안쪽 획득 범위(`rangeX` · `rangeY`)에
  닿으면 그때 먹힙니다. 처음에는 느리게 출발해 가까워질수록 빨라지므로 발밑까지 정확히
  밟지 않아도 결국 먹게 되지만, "빨려 들어온다"는 게 눈에 보입니다.
  튀어오르는 동안과 플레이어가 쓰러져 있는 동안에는 끌리지 않습니다.
- 생명과 코인은 둘 다 **아이콘 하나 + `X nn`** 으로 적습니다. 개수를 아이콘으로 나열하면
  생명이 늘어났을 때 오른쪽 표시(스테이지 · 시간)를 밀고 들어갑니다.

#### 강화 아이템

| 종류 | 효과 | 지속 |
|---|---|---|
| `attack` | 공격력 **누적 강화** | 한 판 내내 (게임 오버까지) |
| `speed` | 이동 속도 1.42배 | 10초 |
| `shield` | 한 대를 대신 맞고 사라진다 | 시간 제한 없음 (그 스테이지 동안) |

- **공격력만 성격이 다릅니다.** 시간제 버프가 아니라 먹을 때마다 쌓이는 강화입니다.
  하나당 기본 공격력(12)의 **+15%** 씩 더해지고 **10개(2.5배 = 30 대미지)** 에서 멈춥니다
  (`CONFIG.power`). 스테이지가 바뀌어도, 쓰러졌다 컨티뉴해도 유지되고 새 판에서만 0 으로 돌아갑니다.
  하나로 판이 뒤집히지 않는 대신 조금 더 자주 떨어집니다.
- 시간제 버프(`speed` · `shield`)는 **중첩되지 않습니다.** 같은 걸 다시 먹으면 시간만 갱신되고,
  종류가 다르면 둘이 함께 걸립니다. 쓰러지면 사라지고, 스테이지가 바뀌면 초기화됩니다.
- 이펙트는 발밑에 **캐릭터보다 먼저** 그려서 몸에 가려지게 뒀습니다. 발끝보다
  `CONFIG.buffs.offsetY` 만큼 더 내려 바닥에서 피어오르게 잡았습니다. 공격력은 상시 이펙트가
  없고, 먹은 직후 1초 동안만 오라가 뜹니다.
- HUD 에 아이콘과 남은 초가 뜹니다. 공격력은 폰트에 소수점이 없어 `LV 3` 단계로,
  보호막은 시간이 아니라 한 번 막을 때까지라 `ON` 으로 적습니다.

### 점수

처치로 버는 점수는 자잘하고, **점수의 대부분은 스테이지를 끝내는 데서 나옵니다** (`CONFIG.score`).

| 항목 | 값 |
|---|---|
| 스테이지 클리어 | 40,000 / 56,000 / 72,000 / 92,000 / 116,000 / — |
| 잔여 시간 (초당) | 200 / 250 / 300 / 350 / 420 / — |
| 노히트 (한 대도 안 맞고 클리어) | 20,000 / 26,000 / 32,000 / 38,000 / 46,000 / 24,000 |
| 완주 (코인을 한 번도 쓰지 않음) | 120,000 |
| 처치 | 20 ~ 135. 보스는 6배 |
| 스테이지 6 처치 | 위 값의 **12배** (클리어·시간 보너스가 없는 대신) |

보스가 60초에 나오므로 잔여 시간 보너스는 스테이지당 최대 4분치입니다. 여섯 스테이지를
한 대도 안 맞고 코인도 안 쓰고 보스를 즉시 잡으면 계산상 **100만을 넘습니다.** 표시가 여섯
자리라 점수는 **999,999** 에서 멈추므로, 완벽하게 가면 만점에 닿습니다.

클리어 화면에 이번 스테이지에서 번 내역이 그대로 뜹니다. 1~5 스테이지는 그 스테이지 배경 위에
`STAGE CLEAR` 와 내역만 얹고, **마지막 스테이지(6)를 끝냈을 때만** `illust_clear.png` 로 화면을
덮고 `GAME CLEAR` 를 띄웁니다. 보스를 쓰러뜨린 플레이어는 그동안 **승리 모션**을 돌립니다
(`player_clear` 애니메이션. 없으면 그냥 서 있습니다).

내역은 한꺼번에 뜨지 않고 **한 줄씩 쾅 하고 박힙니다.** 줄마다 `CONFIG.stageClear.stampIntervalMs`
간격으로 크게 들어왔다가 제자리 크기로 줄고, 그때마다 효과음과 화면 흔들림이 붙습니다.
맨 마지막 `TOTAL` 은 더 세게 찍습니다.

### 랭킹

게임 오버 뒤 이름을 넣으면 점수 · 스테이지와 함께 기록됩니다.

- 문자표에서 커서를 옮겨 한 글자씩 고릅니다. `SP` 공백, `DEL` 한 글자 지우기, `END` 확정.
  비트맵 폰트에 있는 글자만 쓸 수 있어 **A-Z · 0-9 · 공백**, 최대 16글자입니다.
- 상위 **100개**까지 남고, 1페이지는 1~10위를 크게, 2페이지부터 20개씩 목록으로 보여줍니다.
  위아래로 페이지를 넘기고, 왼쪽 `BACK` 으로 나옵니다.
- `run-game.bat` 으로 띄웠으면 기록은 서버가 **`data/scores.json`** 에 저장하므로
  같은 LAN 의 모든 기기가 같은 랭킹을 봅니다 (화면 우측 상단 `SHARED ON THIS SERVER`).
  `file://` 로 열었거나 서버가 없으면 그 브라우저의 `localStorage` 에만 남습니다
  (`SAVED IN THIS BROWSER ONLY`).

이름은 서버에서도 폰트에 있는 글자만 남기고 16자로 자릅니다.

| 메서드 | 경로 | 동작 |
|---|---|---|
| `GET` | `/api/scores` | 정렬된 상위 100개 |
| `POST` | `/api/session` | 1회용 기록 토큰 `{token, secret}` 발급 |
| `POST` | `/api/scores` | `{name, score, stage, at, token, sig}` 기록 후 갱신된 목록 반환 |

#### 기록 위조 막기

예전에는 `POST /api/scores` 가 완전히 열려 있어서 **`curl` 한 줄이면 아무 점수나 꽂을 수
있었습니다.** 실제로 그렇게 올라온 기록이 발견돼서 아래 다섯 겹을 넣었습니다.

| 겹 | 하는 일 |
|---|---|
| 세션 토큰 | 기록하려면 먼저 `POST /api/session` 으로 1회용 토큰을 받아야 합니다. 발급 IP 에 묶이고, 기록이 실제로 들어갔을 때만 소모되고, 3시간이면 만료됩니다 |
| 서명 | 본문을 그 세션의 열쇠로 HMAC-SHA256 서명합니다 (`js/sign.js`). 서명이 안 맞으면 거절 |
| 출처 검사 | `Sec-Fetch-Site: same-origin` (없으면 `Origin`/`Referer` 의 host)이 서버와 같아야 합니다. `Content-Type: application/json` 도 요구합니다 |
| 타당성 검증 | 스테이지별 점수 상한(`STAGE_SCORE_CAP`)을 넘으면 거절. 토큰을 받은 뒤 스테이지당 최소 45초는 지나야 그 스테이지 기록을 받습니다 |
| 레이트 리밋 | IP 당 10분에 세션 40회 · 기록 20회 |

**완전 차단은 아닙니다.** 열쇠가 브라우저 안에 있는 이상 게임 코드를 읽으면 우회할 수
있습니다. 클라이언트를 신뢰하는 구조에서 이건 원리적으로 못 막습니다. 목적은
"URL 을 알아냈다" 수준의 조작을 무의미하게 만드는 것이고, 거기까지는 확실히 막습니다.

거절된 요청은 서버 콘솔에 `[거절] <IP> <사유>` 로 남습니다.

`crypto.subtle` 은 https 나 localhost 에서만 존재해서 폰이 `http://192.168.x.x` 로 들어오면
쓸 수 없습니다. 그래서 SHA-256 · HMAC 을 `js/sign.js` 에 직접 넣었습니다.

### 화면 · 소리 토글

로비 메뉴 아래 두 버튼입니다. 둘 다 **기본이 켜짐**이고, 누를 때마다 켜짐/꺼짐만 오갑니다
(볼륨 단계나 강도 조절은 일부러 두지 않았습니다). 아이콘 아래 `ON` / `OFF` 로 상태를 표시하고,
꺼진 버튼은 흐리게 그립니다. 설정은 저장하지 않아 새로고침하면 둘 다 다시 켜집니다.

- **스피커**: 효과음과 BGM 을 한꺼번에 음소거합니다. BGM 은 멈추지 않고 계속 흐르다가
  다시 켜면 이어서 들립니다.
- **화면**: 옛날 오락기 브라운관 필터입니다. 켜져 있으면 화면 전체에 이런 효과가 걸립니다.

| 요소 | 방식 |
|---|---|
| 주사선 + RGB 섀도우마스크 | 3x3 타일 패턴을 `multiply` 로 한 번 깔기 |
| 가장자리 비네팅 | 미리 만들어둔 radial gradient |
| 아래로 흐르는 밝은 띠 | linear gradient 를 `lighter` 로 |
| 밝기·채도 보정 | CSS `filter: brightness(1.32) saturate(1.2)` — 주사선이 깎아낸 밝기를 되돌립니다 |

픽셀을 직접 훑지 않고 `fillRect` 세 번으로 끝나서 매 프레임 그려도 부담이 없습니다.
세기는 `CONFIG.crt` 에서 조절합니다. 밝기 흔들림(`flicker`)은 광과민성 발작 위험이 없도록
아주 얕게(0.025) 잡아뒀습니다.

### 사운드

효과음은 `assets/sfx/`, BGM 은 `assets/bgm/` 에 두고 매니페스트에 실린 것만 재생합니다.
없는 파일은 요청조차 하지 않으므로, BGM 을 아직 안 넣었어도 게임은 조용히 돌아갑니다.

| 효과음 | 시점 | | BGM | 화면 |
|---|---|---|---|---|
| `attack` | 공격 모션 시작 | | `lobby` | 로비 |
| `hit` | 플레이어 피격 | | `stage1` ~ `stage6` | 스테이지별 |
| `enemy_die` | 적 격파 | | `clear` | 스테이지 클리어 |
| `heal` | 아이템 획득 · 보호막 소모 | | `countdown` | 컨티뉴 |
| `coin` | 코인 투입 | | `gameover` | 게임 오버 · 이름 등록 |
| `button` | 메뉴 이동 · 선택 | | `ranking` | 랭킹 |
| `countdown` | 컨티뉴 카운트다운 (11초) | | | |

브라우저는 사용자 입력이 있기 전에는 소리를 내주지 않으므로, **첫 입력이 들어온 순간** 잠금이
풀립니다. 그전까지는 재생을 시도하지 않고 곡 이름만 기억해 두었다가 잠금이 풀린 다음 프레임에 틉니다.
(재생에 실패했는데 "트는 중"으로 표시해 두면 이후 영영 다시 시도하지 않게 됩니다.)

효과음은 겹쳐 나도록 소리마다 인스턴스를 4개씩 돌려쓰고, BGM 은 재생할 때 스트리밍합니다.

## 용량

에셋을 원본 그대로 쓰면 60MB 가 넘는데, 도트 느낌을 살리는 방향으로 줄여 **15MB** 로 굽습니다.

| | 원본 | 최적화 후 |
|---|---|---|
| BGM 12곡 | 53MB | 14.1MB |
| 스프라이트 · 배경 · 일러스트 · 폰트 | 8MB | 1.0MB |
| 효과음 7개 | 884KB | 122KB |

- **시트를 논리 크기의 절반으로 굽습니다.** 매니페스트에는 원본 크기가 남고 게임은 그 크기로 그리므로,
  좌표·히트박스·밸런스는 하나도 건드리지 않은 채 PNG 만 1/4 이 됩니다.
  확대해서 그려지니 도트가 굵어져 오히려 레트로해집니다.
- 캔버스와 오프스크린 버퍼 모두 **보간을 끄고**(`imageSmoothingEnabled = false`,
  CSS `image-rendering: pixelated`) 확대하므로 흐려지지 않고 픽셀이 그대로 커집니다.
- PNG 는 전부 팔레트로 양자화합니다 (스프라이트 64색, 배경 64색, 폰트 32색).
- 배경과 일러스트는 캔버스 크기로 늘려 그려지므로 512x384 로만 구워도 충분합니다.
- 오디오는 ffmpeg 으로 **모노 22050Hz mp3** 로 다시 굽습니다 (BGM 48kbps, 효과음 64kbps).
  ffmpeg 이 없으면 원본을 그대로 복사하고 넘어갑니다.

수치는 `tools/build_sprites.py` 위쪽 상수(`SPRITE_SCALE`, `SPRITE_COLORS`, `BG_SIZE`,
`BGM_BITRATE` …)에 모여 있습니다. 더 줄이거나 되돌리려면 그 값만 바꿔 다시 구우면 됩니다.

## 에셋 교체

원본은 256x256 / 8프레임 / 투명 배경 GIF 입니다. canvas 의 `drawImage` 는 애니메이션 GIF 의
프레임을 제어할 수 없으므로, 가로로 이어붙인 스프라이트시트 PNG 로 미리 변환해서 씁니다.

**원본 폴더는 통째로 줘도 되고 일부만 줘도 됩니다.** `assets/sprites.json` 이 이미 있으면 그 위에
이번에 찾은 것만 덮어쓰므로, 에셋이 하나씩 도착할 때마다 그것만 구우면 됩니다.

```
<원본>/player_idle.gif  player_walk.gif  player_attack.gif  player_hit.gif
<원본>/player_kick.gif  player_clear.gif      (선택. 없으면 게임이 attack / idle 로 대체)
                       player_victory.gif    (player_clear.gif 의 별칭. 둘 중 아무 이름이나 된다)
<원본>/game_bg.png                            스테이지 2(디트로이트) 배경
<원본>/bg_stage1.png ... bg_stage6.png        없는 번호는 game_bg 로 남는다
<원본>/illust_clear.png                       게임 클리어(마지막 스테이지) 연출 일러스트
```

아이콘은 `sprites/` 아래를 먼저 보고 없으면 원본 폴더 바로 아래에서 찾습니다.
오디오는 변환 없이 이름만 게임이 부르는 쪽으로 정리하고(`game over` → `gameover`, 공백은 `_` 로),
폴더를 통째로 비우지 않고 **같은 이름만 갈아끼웁니다.**

변환:

```bash
python tools/build_sprites.py <원본_에셋_폴더>
```

`assets/` 에 시트 PNG 와 `sprites.js`(`window.SPRITE_MANIFEST`)가 생성됩니다.
매니페스트의 `frameWidth` · `frameHeight` · `anchorX` 는 **줄이기 전 원본 크기**입니다.
게임이 그 크기로 그리기 때문에, 시트를 더 줄이거나 되돌려도 게임 쪽은 손댈 필요가 없습니다.
`file://` 에서는 `fetch` 로 JSON 을 읽을 수 없어 매니페스트를 JS 전역으로도 굽습니다.

아이콘 원본에 투명 표시용 체커보드가 **픽셀로 그려져** 있으면(내려받은 아이콘이 흔히 그렇습니다)
가장자리에서 이어진 밝은 무채색 영역만 골라 투명으로 바꿉니다. 아이콘 안쪽의 흰색 하이라이트는
가장자리와 이어져 있지 않으므로 그대로 남습니다.

한 캐릭터의 모든 애니메이션은 **공통 x 범위로 크롭**되고 세로 256 을 그대로 유지합니다.
그래야 애니메이션이 바뀌어도 캐릭터가 떨리지 않고, 발끝이 항상 바닥에 정렬됩니다.
**이미 구운 시트에 애니메이션만 덧붙일 때는 원래 크롭 범위를 그대로 씁니다.**
범위가 달라지면 애니메이션이 바뀔 때마다 캐릭터가 좌우로 떨립니다.

버프 시트(`buff_frames.png`)는 균일 격자로 자른 뒤, 한 종류의 8프레임을 덮는 공통 bbox 로
다시 크롭합니다. 프레임마다 따로 자르면 이펙트가 프레임 사이에서 떨립니다.

### 폰트

`font.png` 는 A-Z / 0-9 가 6x6 으로 배치된 시트입니다. 칸 폭이 균일하지 않아 6등분으로는
정확히 잘리지 않으므로, 알파가 비어있는 구간을 찾아 행·열 밴드를 검출한 뒤 글리프마다 다시
타이트하게 자릅니다. 모든 글리프가 칸 위쪽에 정렬되어 있어 위 기준으로 맞추면 베이스라인이 맞습니다.

**폰트에 없는 글자는 그려지지 않습니다.** 그래서 게임 내 문구는 전부 영문 대문자이고,
하이픈·콜론이 없어 `HI-SCORE` 대신 `HI SCORE` 처럼 공백을 씁니다. 스테이지 이름도 같은 제약을
받습니다 (`TESLA SPACESHIP`, `MYSTERY ZONE` …). 문구를 바꿀 때 주의하세요.
